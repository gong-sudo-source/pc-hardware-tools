# 당근 컴퓨터 쌀먹 V2

Next.js App Router + TypeScript + Tailwind + Supabase(Auth/Postgres/Storage/RLS). 개인용 PC/부품 거래 장부입니다. 앱은 Vercel, 거래 기록은 Supabase DB, 사진은 비공개 Storage에 각각 저장합니다. **같은 Supabase 프로젝트를 연결하는 한 코드 수정·재배포로 거래 데이터가 초기화되지 않습니다.** PC 정보는 저장 버튼으로, 부품 표와 사진 변경은 입력 후 약 1초 내 자동으로 저장됩니다. 자동 저장 완료 표시를 확인하고 이동하세요. 다른 기기에서는 새로고침으로 최신 기록을 불러옵니다.

## 로컬 실행

Node.js 20.9 이상과 npm 또는 pnpm이 필요합니다.

```sh
npm install
cp .env.example .env.local
npm run dev
```

Windows PowerShell에서는 `Copy-Item .env.example .env.local`을 사용하세요. http://localhost:3000 으로 접속합니다. 환경변수 없이 실행하면 연결 안내 화면이 나옵니다. Supabase 설정 후 서버를 다시 시작하세요.

## Supabase 최초 설정

1. 새 Supabase 프로젝트를 만들고 URL과 publishable/anon key를 `.env.local`에 입력합니다. **service_role 키는 앱에 넣지 않습니다.**
2. SQL Editor에서 `supabase/migrations/202610090001_initial.sql`과 `supabase/migrations/202610090002_legacy_fields.sql`, `supabase/migrations/202610090003_workflow.sql`을 순서대로 한 번씩 실행합니다. CLI 사용자는 프로젝트 연결 후 `supabase db push`를 사용하세요. 이미 초기 SQL을 수동 실행했다면 migration history를 정합화한 후 CLI로 전환하세요.
3. SQL Editor에서 `insert into public.allowed_users(email) values ('내이메일@example.com');`를 실행합니다. 소문자로 입력하고 테이블에 이메일을 정확히 하나만 유지하세요. 빈 허용목록은 모든 접근을 거부합니다. 허용목록은 클라이언트에서 읽거나 수정할 수 없습니다.
4. Authentication 설정에서 **신규 회원가입을 끄고**, Users의 Add user로 이메일/비밀번호 계정 하나를 생성합니다. 이메일 확인을 완료하거나 관리자 생성 시 확인 완료로 설정합니다. 앱에는 회원가입 화면이 없습니다. 비밀번호 변경/복구는 초기 버전에서 Supabase 관리자가 처리합니다.
5. Auth의 Site URL을 운영 URL로 설정합니다. 서버 API에도 같은 이메일을 `ALLOWED_EMAIL`로 지정하세요. 보안 경계는 DB 허용목록과 RLS이며 서버 환경변수만으로 DB 접근을 제한하는 구조가 아닙니다.
6. 해당 계정으로 로그인하고 PC 저장→새로고침→다른 기기 로그인 순으로 확인합니다.

## GitHub / Vercel 배포

현재 운영 주소: https://carrot-pc-ledger.vercel.app/

Vercel 프로젝트 `jig2/carrot-pc-ledger`에 CLI로 첫 운영 배포를 완료했습니다. 기존 Supabase를 사용하므로 이전 계정으로 로그인하면 같은 기록을 불러옵니다. 2026-10-21 GitHub 커밋의 Vercel 배포 성공을 확인했습니다. 코드 수정 후 검사하고 커밋의 Vercel 배포 상태를 확인하세요. CLI 재배포도 가능합니다. `.vercelignore`로 로컬 환경 파일·참조 자료·작업용 스크린샷·관리용 SQL을 업로드에서 제외합니다. DB migration은 앱 배포와 별개이며 재배포할 때 초기 SQL을 재실행하지 않습니다.

1. 이 프로젝트를 개인 GitHub 저장소에 올립니다. `sources/`는 읽기 전용 참조 자료이며 배포할 필요가 없습니다. `.env.local`은 커밋하지 마세요. `pnpm-lock.yaml` 또는 `package-lock.json`은 커밋합니다.
2. Vercel에서 저장소를 Import합니다. Framework는 Next.js, Root Directory는 이 앱 폴더입니다.
3. Vercel 환경변수에 Supabase URL/anon key/ALLOWED_EMAIL을 입력합니다. OPENAI_API_KEY는 서버 전용이며 없어도 모든 장부 기능이 동작합니다.
4. Deploy 후 로그인·사진 업로드·판매 기록·JSON 복원을 확인합니다. 이후 GitHub push로 앱만 재배포합니다. 환경변수 변경 시에는 재배포하세요.

## 사용 및 정산

- PC 여러 대, 구매일/구매처/매입가/기타비용/메모 및 대표 사진 한 장을 관리합니다. 부품은 요청된 13개 분류를 지원합니다.
- 화면 입력 단위는 기존 v1.4와 같은 만원이며 DB에는 정수 원으로 저장합니다. 실판매가 미입력은 판매 대기, 0원 포함 숫자 입력은 판매 완료입니다. 보유/판매 등록/예약/판매완료 상태, 별칭, 판매일 수정도 지원합니다. 완료 상태를 미판매로 바꾸면 금액·날짜는 임시 입력값으로 보존하되 회수액에서 제외합니다. 첫 판매일을 한국 시간 기준으로 기록하고 수정 시 유지합니다. 실판매가를 비우면 판매일도 해제합니다. DB 트리거가 이를 검증합니다.
- 추천가 대비 실판매가가 높으면 초록, 낮으면 빨강, 동일하거나 추천가가 없으면 기본색입니다.
- 매입비=매입가+기타비용. 회수액=판매된 부품 실판매가 합계. 현재 손익=회수액−매입비. 남은 예상액=미판매 부품의 등록가(없으면 AI 추천가, 둘 다 없으면 0). 예상 최종 회수=회수액+남은 예상액. 예상 순이익=예상 최종 회수−매입비. 예상 수익률=예상 순이익/매입비×100(매입비 0이면 미표시).
- 콤보와 개별 부품의 중복 등록은 중복 정산됩니다. 하나의 실제 판매 단위마다 한 행으로 등록하세요.
- JSON 백업은 **저장된 DB 기록**을 내보냅니다. 저장하지 않은 화면 변경은 포함하지 않습니다. 복원은 검증 후 원자적으로 **추가**하며 기존 기록을 덮어쓰지 않습니다. 재복원은 중복 PC를 만듭니다. PC/부품 ID를 새로 발급하며 판매가는 보존합니다.
- 새 JSON 백업과 열람용 HTML은 사진 원본도 포함합니다. 사진을 읽지 못하면 백업을 중단해 누락을 알립니다. 사진 포함 백업은 다른 프로젝트에서도 업로드 후 복원할 수 있습니다. 예전 V2 백업처럼 사진 경로만 있으면 같은 프로젝트/사용자일 때만 연결이 유지됩니다. 이전 v1.4 JSON 또는 기록 포함 HTML도 가져올 수 있으며 만원 금액을 원으로 변환합니다. 원본 HTML의 embeddedState가 null이면 거래 데이터가 없는 파일이므로 기존 브라우저에서 JSON을 내보내야 합니다.

## 보안 및 AI API

RLS는 로그인 사용자 소유권과 DB 이메일 허용목록을 동시에 검사합니다. Storage는 비공개 버킷과 사용자 ID 폴더 정책을 적용하며 사진은 만료되는 서명 URL로 열립니다. 사진은 JPG/PNG/WebP, 최대 5MB입니다. 부품은 PC 행의 JSONB 배열로 저장하며 전체 PC 편집/판매 기록 변경을 한 번의 DB 쓰기로 반영합니다. 동일 PC를 두 기기에서 동시에 수정하면 수정 시각을 비교해 뒤늦은 저장을 거부합니다. 충돌 시 화면의 변경을 별도로 보관하고 새로고침 후 PC를 다시 열어 반영하세요.

`POST /api/pricing`은 서버에서 Supabase 토큰·이메일·RLS 허용목록과 요청 형식을 검증합니다. **현재는 안전한 연결 경계만 구현했으며 실제 OpenAI 호출/시세 추천은 활성화하지 않았습니다.** 키 유무와 관계없이 준비 안내를 반환하고 수동 추천가 입력을 지원합니다. 활성화 전에는 신뢰할 시세 소스, 영속적 사용자별 요청 제한/비용 한도, 서버 응답 스키마 검증, 타임아웃을 구현해야 합니다. API 키를 `NEXT_PUBLIC_` 변수에 넣지 마세요. 추천가를 실제 시장 거래가로 오인하게 만드는 가짜 응답은 생성하지 않습니다.

## 데이터 보존 및 마이그레이션 원칙

1. 운영 DB의 reset/drop/truncate, 테이블 재생성, Auth 사용자 삭제를 하지 않습니다. 앱 빌드·시작 시 DB 초기화나 seed를 실행하지 않습니다.
2. 기존 migration 파일을 수정하지 말고 날짜순 새 파일을 추가합니다. 초기 migration은 새 DB용입니다.
3. 먼저 nullable 열/새 테이블 추가 → 기존 데이터 보충 → 구버전·신버전 호환 확인 → 이후 제약 적용 순서로 진행합니다. 파괴적 변경은 별도 백업·복구 검증과 명시적 승인이 필요합니다.
4. 운영 변경 전에 Supabase DB 백업/스냅샷과 Storage 원본을 보관하고 스테이징에서 migration과 복구를 시험합니다. JSON만으로 Auth/RLS/Storage 전체를 복구할 수 없습니다.
5. `allowed_users`, RLS, Storage 정책, RPC 권한은 새 기능에서도 유지합니다. 새 테이블에도 RLS를 적용합니다. Supabase 프로젝트/키를 다른 프로젝트로 교체하면 기존 데이터가 자동 이동하지 않습니다.
6. 판매 이력은 현재 판매가/판매일을 유지하는 모델입니다. 가격 변경의 모든 과거 버전을 기록하는 감사 로그나 다중 판매/부분 환불은 포함하지 않습니다.

공식 구조 참고: [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control).



## v1.4 화면 이식

첨부된 pc_flip_ledger_v1_4.html의 CSS와 화면 구성을 React 컴포넌트로 옮겼습니다. 기존 HTML은 수정하지 않았습니다. 카드 목록, 현재 실적·회수율, 구성품 표, PC 추가/정보 수정, 판매 상태, 사진 5세트 선택, 백업, 열람용 HTML 저장을 지원합니다. 기존 화면의 현재 실적을 유지하고 V2의 예상 최종 정산을 별도 패널에 표시합니다. 사진 자료는 public 폴더에 두지 않고 인증·허용목록 검증을 거치는 서버 API로만 제공합니다. 사진 선택 시 비공개 Supabase Storage에 업로드합니다. 사양만으로 다른 PC의 사진이 연결되지 않도록 새 PC의 대표 사진은 사용자가 직접 선택합니다.

기존 로컬 브라우저의 localStorage를 서버에서 직접 가져올 수는 없습니다. 원래 거래 내역이 보이는 HTML을 그 브라우저에서 열어 ‘백업 내보내기’를 누른 후, V2의 ‘백업 불러오기’로 JSON을 선택하세요. 가져오기는 기존 기록을 지우지 않고 추가합니다. 구매일·판매일이 없으면 가져오는 날짜를 사용하며 적용 전에 경고합니다. 외부 이미지 URL은 임의로 다운로드하지 않고 오류로 알려줍니다. 기존 파일의 내장 사진은 그대로 가져옵니다.

## 배포 전 작업 흐름 개선

- 새 PC는 CPU → 메인보드 → RAM → SSD → PSU → 케이스 → GPU 7개로 시작합니다. 기존 PC의 부품은 바꾸지 않습니다. 왼쪽 손잡이를 마우스/터치로 끌거나 위아래 버튼·키보드 화살표로 순서를 바꿉니다.
- 추천가는 외부 AI를 호출하지 않고 같은 분류·정확히 일치하는 모델명(공백/대소문자 정규화)의 내 실제 판매 기록 중앙값을 사용합니다. 등록 범위 초안은 그 기록의 최저~최고 실판매가입니다. 기록이 없으면 채우지 않습니다. 모델명 입력을 마치면 빈 추천값을 자동으로 채우며, 수동 입력값은 덮어쓰지 않습니다. 오래된 기록일 수 있고 현재 시장 시세가 아니므로 화면의 표본 수와 금액을 확인하세요.
- 등록 범위의 하한은 네고 기준, 상한은 시작 가격으로 직접 수정합니다. 실판매가가 하단에 가까우면 빨강, 상단이면 초록, 중간이면 옅은 황금색입니다. 범위를 크게 벗어날수록 진해집니다. 추천가와의 비교 색상은 사용하지 않습니다.
- 개인 보관은 판매 대기/남은 예상액에서 제외하지만 이미 지출한 매입비는 유지합니다. 판매완료 부품은 보관 표시가 불가능합니다. 보관 표시를 해제하면 다시 판매 대기로 돌아옵니다.
- 판매일은 편집 화면에서 숨겼습니다. 기존 DB 값과 백업 데이터는 삭제하지 않습니다.
